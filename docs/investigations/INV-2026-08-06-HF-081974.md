# INV-2026-08-06 — HeroForge Build 08.1.9.74 Compatibility Investigation

**Date:** 2026-08-06  
**Status:** Findings recorded; Stage 1 standalone implementations created; live validation pending  
**Build:** `heroforge08.1.9.74`

## Evidence

Two read-only Tampermonkey probes were run against an otherwise unmodified HeroForge session.

| Bundle | SHA-256 |
|---|---|
| `creationkit.js` | `f409276a1e6f5b3f1533f3922947c224f98fac61fa9a087834a93968727850c0` |
| `heroforgeui.js` | `c70ff17533376fe18f499beacefce10aef8da6d4ed4d270c127aa683bc5ad572` |
| `boothui.js` | `951ab2a272b8ee57c7d82bc2b317fa1c7a17e01e4dd2ef7d48ce1ce691643c78` |

The probes reported no internal errors and observed the required runtime after the relevant HeroForge areas were opened.

## Confirmed findings

### Bundle split

Photo Booth controls and capture code moved from `heroforgeui.js` into the new `boothui.js` bundle.

Confirmed moved code includes:

- screenshot-size option generation,
- Spinny Mini capture actions,
- Booth camera controls,
- Booth environment/light option rendering,
- Booth overlay transform controls.

Legacy scripts that intercept only `heroforgeui.js` cannot modify this code.

### Character JSON runtime

The following named surfaces remain available:

- `CK.tryLoadCharacter`
- `CK.character.data.getJson`
- `CK.Helpers.deepCopy`
- `CK.UndoQueue.queue`
- `CK.UndoQueue.currentIndex`
- `CK.saves.getFullConfig`
- `CY.AvatarBrowser`

The HeroForge browser/action React structure changed and at least one legacy action-order anchor became ambiguous. Independent UI is therefore preferred for complete character file I/O.

### Photo Booth settings runtime

The old `TN.tokenizer.effectState` path was absent after Booth initialized.

The current runtime exposes:

- `BT`
- `BT.maker`
- `BT.maker.effectState`
- `BT.maker.effectState.save`
- `BT.maker.effectState.load`

The existence of those methods is confirmed. Their complete serialization contract is not yet live-validated.

### Projected decal renderer

The old exact renderer anchors no longer exist.

The current relevant renderer context uses:

- `ve` for the saved decal transform/state record,
- `pe` for native projected-slot status,
- `ke=!pe||y<2` for the native projected binding decision.

Saved decal records still contain the legacy custom properties:

- `forceProjectedScript`
- `enableUnequalScaling`

They also retain separate `s`, `sy`, and `sz` transform values.

This supports preserving existing character data and repairing only the renderer interpretation plus independent controls.

### Native decal features

HeroForge now includes native:

- projected decal Tiling,
- Apply To controls,
- layer ordering,
- live projected decal uniforms,
- multiple projected display decal handling.

The legacy `forceTilingScript` renderer patch should not be restored without a separate proven requirement.

### Booth capture sizing

The screenshot-size loop exists once in `boothui.js`:

```js
for(var c=512;c<=2*CK.Settings.screenshotSize;)
```

With the observed default `CK.Settings.screenshotSize` of `1024`, HeroForge can generate menu entries through 2048. The legacy `2×` to `4×` modification is still needed only for the old 8K extension behavior.

A missing 2048 menu option and a failed 2048 capture are distinct failure modes and must not be conflated.

## Supported inferences

- Clover's restored Project control is nonfunctional because the current renderer no longer reads `forceProjectedScript`, not because its current UI insertion anchor is absent.
- Existing Unequal Scaling controls are affected by the same cross-script dependency and renderer change.
- Witch Dock Persistent Booth View and Black Canvas Background likely need new `BT.maker`, `BT.display`, or current Booth lifecycle adapters. Their implementation belongs in the Witch Dock project after the shared Booth findings are stable.

## Unproven items

- Exact breadth of data serialized by `BT.maker.effectState.save`.
- Whether `BT.maker.effectState.load` alone restores camera, background, lighting, overlays, and effects.
- Whether the Stage 1 projected renderer substitutions fully preserve native layer-order behavior.
- Whether 2048 capture failures are reproducible independently of GPU, memory, Cloudflare, or other scripts.

## Stage 1 disposition

Created three isolated standalone test modules:

1. `character.local-file-io`
2. `photo-booth.settings-file-io`
3. `decals.transform.projected` including Unequal Scaling

No Witch Dock repository, production userscript, public manifest, or stable module was changed.
